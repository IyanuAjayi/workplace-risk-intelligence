# Workplace Risk Score

Can a site's own public injury record predict its next-year injury risk well enough to improve how workers' compensation insurance is priced?

A two-week internship project for Parakeet Risk (October to November 2026). It links ten years of OSHA injury records for US industrial workplaces, scores each site's chance of a serious-injury year, validates the score on years it never saw, and tests what pricing with it would change. All pricing figures are simulations, not real premiums or losses.

## The product: Workplace Risk Intelligence

A four-page Power BI report under the Parakeet Risk brand: *Predictive insights for industrial insurance underwriting*.

| Page | Question it answers |
| --- | --- |
| Executive Intelligence | Is serious-injury risk concentrated enough to price or act on? |
| Risk Landscape | Where does risk concentrate by band, sector, state and size? |
| Model Trust | Can the score be trusted on years it never saw? |
| Pricing Lab | What would the score change in a simulated premium split? |

The four pages were designed and reviewed as mockups (`powerbi/mockups/`) on the design system in `docs/design-system.md`, then built in the Parakeet Risk Power BI service on 1 Nov 2026 and checked against the verified figures. Screenshots of the live report are in `powerbi/live/`; how it was built is in `docs/powerbi-build-guide.md` and `docs/powerbi-implementation-notes.md`.

## Headline results (test years 2023 and 2024)

| Model | AUC |
| --- | --- |
| Rating class only (sector, size, state, ownership) | 0.59 |
| Last year's rate (the site's rank in its industry) | 0.73 |
| Scorecard (explainable, used for bands and pricing) | 0.78 to 0.79 |
| Gradient boosting | 0.80 |

AUC is measured on all 215,802 test pairs. On the 199,150 private-sector site-years priced in the simulation, the scorecard cuts the share of simulated premium in the wrong risk band from 27.5% to 10.0% (2023) and from 26.7% to 9.3% (2024) at the central claim cost, with total premium held fixed. Every figure a report or design may use is in `docs/verified-metrics.md`.

## Data

- **OSHA Injury Tracking Application (ITA), Form 300A summary data, 2016 to 2025:** https://www.osha.gov/itadata. Download each year's summary file in a browser (osha.gov blocks scripted downloads) into `data/raw/`. File names, sizes and fingerprints are in `docs/extract-log.md`.
- **BLS SOII Table 1 and Table A-1** (industry DART rates and their relative standard errors): read from the bls.gov HTML tables into `data/raw/bls/`. See `docs/benchmarks.md`.
- **Claim cost:** NCCI average lost-time claim via NSC Injury Facts. See `docs/benchmarks.md`.

## Setup

    /usr/bin/python3 -m venv .venv          # Python 3.9
    .venv/bin/pip install -r requirements.txt

`render_backgrounds.py` and `visual_boxes.py` also need Google Chrome (the path is set in each script).

## Rebuild everything

Run from the repository root, in order:

    .venv/bin/python scripts/01_audit.py          # data audit -> docs/data-audit.md, outputs/audit/
    .venv/bin/python scripts/02_build_panel.py    # linked panel and year pairs -> data/final/, docs/panel-note.md (about 6 min)
    .venv/bin/python -m pytest -q tests/          # checks on rates, keys, target and cohort rules
    .venv/bin/python scripts/03_model.py          # train, validate, test -> outputs/model/, models/, docs/model-results.md (about 15 min on a free machine)
    .venv/bin/python scripts/04_pricing.py        # pricing simulation -> outputs/pricing/, docs/pricing-results.md
    .venv/bin/python scripts/05_robustness.py     # linking, target, COVID and subgroup checks -> outputs/model/robustness_*.csv, docs/robustness.md
    .venv/bin/python scripts/08_curves.py         # ROC and precision-recall curve points -> outputs/model/
    .venv/bin/python scripts/09_landscape.py      # state, sector, size and sector-by-band tables, state tile grid -> outputs/landscape/
    .venv/bin/python scripts/06_export_powerbi.py # Power BI workbook and expected values -> outputs/powerbi/ (needs 02 to 05, 08 and 09 first)

Then the report:

    .venv/bin/python powerbi/tools/render_backgrounds.py powerbi/mockups/page*.html   # page backgrounds -> powerbi/backgrounds/
    .venv/bin/python powerbi/tools/visual_boxes.py powerbi/mockups/page*.html         # visual positions -> powerbi/build/
    .venv/bin/python powerbi/tools/measures.py                                        # measures -> powerbi/model/measures.tmdl, outputs/powerbi/measures.dax
    .venv/bin/python powerbi/tools/build_report.py                                    # report definition -> powerbi/report/

Create the semantic model from the workbook, apply `measures.tmdl` in the TMDL view and deploy `powerbi/report/` with the Fabric "update report definition" call, as set out in `docs/powerbi-build-guide.md`. Before sharing, every figure must match `outputs/powerbi/expected_values.csv` and `docs/verified-metrics.md` (the guide lists the checks run on 1 Nov).

Shared helpers live in `src/osha.py`. Random seeds are fixed (42).

## Tools (`powerbi/tools/`)

| Tool | What it does |
| --- | --- |
| `check_numbers.py` | Lists every number on a mockup (HTML) that isn't in `docs/verified-metrics.md`, so each one can be confirmed by hand |
| `check_palette.py` | Checks an ordered colour scale: lightness order, contrast with the background, and separation under simulated colour blindness |
| `compare_sheet.py` | Puts mockup PNGs side by side on one sheet for review |
| `render_backgrounds.py` | Renders each page's background image from its mockup, with the live Power BI visuals hidden |
| `visual_boxes.py` | Lists the position and size of every live visual on a mockup, for placing visuals in Power BI |
| `measures.py` | Holds every DAX measure in one list and writes the TMDL script and the readable listing |
| `build_report.py` | Writes the whole report (four pages, 93 visuals, theme, backgrounds) as a Power BI report definition |

## Limits

OSHA data is employer-reported and covers only sites above the reporting thresholds. The score predicts reported injuries, not claim costs. Pricing is a simulation on stated assumptions. Prediction isn't evidence of cause. Two test years is a solid check, not a long track record.
